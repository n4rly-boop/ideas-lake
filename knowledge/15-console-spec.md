# 15 — Консоль: открытие идеи, состояние вкладок, телефон

Лёгкая спека под три дефекта `lake/api/console.html`, найденные при работе с циферблатом
2026-08-02. Файл один, сборки нет, зависимостей нет — это ограничение остаётся.

Адреса — по состоянию репозитория на коммит `90cdbe3`.

---

## §0 Что сломано

### 0.1 Клик по идее ничего не открывает

`openIdea` объявлена заглушкой и присваивается только внутри монтирования вкладки «Идеи»:

```
console.html:1129   let openIdea = () => {};
console.html:1229   openIdea = (id) => { switchTo("ideas"); setTimeout(() => show(id), 0); };
```

Пока вкладка «Идеи» ни разу не открывалась, `openIdea` — пустая функция. Пять мест зовут
её и все пять мертвы на свежей загрузке:

| Адрес | Что не работает |
|---|---|
| `console.html:876` | клик по узлу-идее на циферблате |
| `console.html:1010` | ссылка `idea_…` в таблице попаданий циферблата |
| `console.html:1093` | ссылка `idea_…` во вкладке «Индекс» |
| `console.html:1272` | ссылка `idea_…` во вкладке «Тезисы» |
| `console.html:1803` | кнопка «Открыть в „Идеях“» во вкладке «Граф» |

Воспроизведение (проверено в браузере): открыть `/ui#dial` заново, разложить гипотезу,
кликнуть узел → `location.hash` остаётся `#dial`, `typeof openIdea === "function"` (это
заглушка), ничего не открывается. После ручного захода во вкладку «Идеи» те же клики
работают. Отсюда и ощущение «через раз».

Второй дефект того же места: `setTimeout(() => show(id), 0)` — гонка с монтированием, а не
передача аргумента. Порядок держится случайно.

### 0.2 Состояние вкладки не переживает переключение

`render()` сносит `#main` и монтирует view заново, состояния нет нигде:

```
console.html:1908   function render() {
console.html:1914     main.replaceChildren();
console.html:1917     chosen.mount(main);
```

Проверено: на циферблате запрос + 12 строк таблицы + SVG; переход `#search` и обратно на
`#dial` → поле пустое, строк 0, SVG нет. Теряется:

- циферблат: текст гипотезы, `k`, число идей, флаги «идеи и рёбра» / «точки-листья», сам ответ;
- retrieve: запрос, `k`, ответ, обе руки абляции;
- идеи / тезисы / источники: `offset` и фильтры (`state` живёт в замыкании mount, `console.html:1133`);
- ингест: развёрнутая очередь заданий и автообновление.

Переживает переключение только `GRAPH_CACHE` и `LEAF_TEXT` — они объявлены на модуле
(`console.html:591`, `:594`), а не внутри view.

### 0.3 Телефона нет

На весь файл одна медиа-строка:

```
console.html:151   @media (max-width:1100px){.ab{grid-template-columns:1fr}}
```

`<meta name="viewport">` на месте (`console.html:5`), дальше всё сделано под десктоп:

- `nav.tabs{position:sticky;top:53px}` (`console.html:48`) — 53 px это высота хедера в одну
  строку. На узком экране хедер переносится (`flex-wrap:wrap`, `console.html:35`) и занимает
  две-три строки: полоса вкладок налезает на чипы или висит с разрывом.
- `label.f.grow{flex:1 1 340px}` (`console.html:67`) — поле не сжимается ниже 340 px, ряд
  контролов ломается на телефоне шириной 390.
- Таблицы (`table.tbl`, `console.html:93`) по 7 колонок в `.scroller{max-height:60vh}`
  (`console.html:101`): горизонтальный скролл внутри вертикального, читать нечем.
- Циферблат считает размер от ширины обёртки и высоты окна
  (`console.html:736`): на 390 px радиус выходит ~150 px, 3 040 точек в такой круг — каша,
  а узлы идей 7–11 px перекрывают друг друга.
- **Наведения на телефоне не существует.** Карточка привязана к `mousemove` и
  `mouseleave` (`console.html:942`, `:988`). Тач их не шлёт — после переноса текста в
  ховер (коммит `90cdbe3`) на телефоне текста не видно вообще нигде, кроме таблицы под
  циферблатом. Это регрессия ровно для того сценария, который назвал владелец: «тыкать
  будут с телефона».

## §1 Что должно стать правдой

1. Клик по идее открывает идею — с первого раза, из любой вкладки, без предварительного
   визита в «Идеи».
2. Ссылка на состояние — это URL. Открытая вкладка, запрос гипотезы и параметры выдачи
   восстанавливаются из адреса; переключение вкладок туда-обратно ничего не теряет.
3. Консоль работает пальцем на экране 390×844: контролы в один столбец, таблицы читаемы,
   текст метки достаётся тапом, циферблат остаётся честным (числа те же, что на десктопе).
4. Ни одна из правок не добавляет зависимость, сборку и второй файл.

## §2 Решения

### 2.1 Маршрут вместо заглушки

Хеш становится двусоставным: `#<tab>` или `#<tab>/<arg>`.

```
#dial                     вкладка
#ideas/idea_8465d6783476  вкладка + аргумент
```

- `parseHash(hash) -> {tab, arg}` и `formatHash(tab, arg)` — две чистые функции рядом с
  роутером (`console.html:1900`).
- Сигнатура view меняется: `mount(host, ctx)`, где `ctx = {arg, state}`. Вкладка «Идеи»
  на монтировании сама зовёт `show(ctx.arg)`, если аргумент есть.
- `openIdea(id)` становится одной строкой: `location.hash = formatHash("ideas", id)`.
  Заглушка `console.html:1129` и `setTimeout(…, 0)` (`console.html:1229`) удаляются.
- Побочный выигрыш: ссылка на конкретную идею становится ссылкой, которую можно кинуть
  в чат.

Аргумент — только идентификатор идеи (`idea_…`). Ничего длиннее в путь хеша не кладём:
запрос гипотезы едет в query-часть, см. 2.2.

### 2.2 Состояние: параметры — в URL, ответы — в памяти

Правило деления:

| Что | Где живёт | Почему |
|---|---|---|
| вкладка, аргумент | хеш | это адрес |
| текст гипотезы, `k`, число идей, флаги, `offset`, фильтры | query внутри хеша: `#dial?q=…&k=12&top=30&leaves=1` | параметры воспроизводят вид и передаются ссылкой |
| тела ответов (`/dial`, `/retrieve`, страницы) | `VIEW_STATE` — `Map` на модуле, рядом с `GRAPH_CACHE` (`console.html:591`) | 285 КБ на вызов; в `sessionStorage` это данные озера в хранилище браузера, а туда мы ничего из озера не кладём (README, раздел про `/ui`) |

Механика:

- `const VIEW_STATE = new Map()` — ключ `tab`, значение — объект вкладки. `render()`
  передаёт его в `mount` и никогда не чистит.
- View на монтировании: если в состоянии лежит прошлый ответ — **рисует его**, не повторяя
  запрос. Кнопка «Разложить» / «Спросить» остаётся единственным способом сходить в сеть.
- Из URL восстанавливаются только параметры. **Автозапроса при открытии нет** — на
  телефоне это чужой трафик и лишний вызов; поле заполнено, кнопка подсвечена. Исключение
  одно: явный `&run=1` в ссылке, чтобы «покажи вот это» открывалось само.
- `switchTo` и обработчик `hashchange` (`console.html:1902`, `:1920`) переписываются под
  `parseHash`; текущая склейка `location.hash.slice(1)` уходит.

Что НЕ сохраняем: ключ (`sessionStorage`, решение прежнее), автообновление очереди
заданий (таймер должен умирать вместе с вкладкой — иначе фоновые запросы с телефона).

### 2.3 Телефон

**Брейкпоинты:** 900 (планшет/узкий десктоп), 620 (телефон-ландшафт), 430 (телефон).

**Шапка и вкладки.** Убрать магию `top:53px`. Хедер и полоса вкладок — один
`position:sticky` контейнер, тогда смещение считать не нужно вовсе. Чипы статистики на
узком — горизонтальный скролл-ряд (`overflow-x:auto`, `flex-wrap:nowrap`), без переноса.

**Контролы.** При `max-width:620`: `.row{flex-direction:column;align-items:stretch}`,
`label.f.grow{flex-basis:100%}`, `.panel{padding:12px 12px}`, кнопки во всю ширину,
минимальная площадь касания 44×44 (сейчас `.ghost.sm` меньше).

**Таблицы.** Два разных решения, потому что задачи разные:

- «Идеи», «Тезисы», «Источники», таблица попаданий циферблата — на узком превращаются в
  карточки: каждая строка — блок, подписи из `<th>` едут в `data-label` и печатаются
  псевдоэлементом. Колонок 6–7, скролл тут бесполезен.
- Служебные (очередь заданий, отказы арбитра) — оставить скролл, туда с телефона не смотрят.

**Циферблат.**

- Квадрат по ширине: `h = min(w, 0.7 * innerHeight)`, сейчас высота от окна независимо от
  ширины (`console.html:736`).
- Точки-листья при `w < 430` по умолчанию **выключены**, и статус это говорит словами
  («листья скрыты: экран 390 px»). Число `total` в статусе не меняется — оно про ответ,
  а не про то, что нарисовано.
- Радиусы меток и `gapPx` раскладки (`ringLayout`, `console.html:626`) масштабировать от
  ширины: на 390 px узел ~5 px, метка попадания ~5 px, кольцевой зазор ~12 px.
- Число идей по умолчанию на узком — 15, не 30 (в кольцо на 390 px больше не встаёт;
  причина та же, что уже описана в README).

**Тач вместо ховера.**

- `mousemove`/`mouseleave` (`console.html:942`, `:988`) заменить на `pointermove` +
  `pointerdown`, ветка по `event.pointerType`.
- Палец: тап по метке — показать карточку; тап по той же метке второй раз — открыть идею
  (для узла-идеи); тап мимо — скрыть. Никакого «наведения» и никакой зависимости от
  `:hover` в CSS для содержательных элементов.
- Радиус поиска ближайшей метки: 9 px мышью, 18 px пальцем (сейчас порог 9 —
  `console.html:951`).
- При `max-width:620` карточка не следует за пальцем, а прижимается к низу экрана на всю
  ширину (палец её иначе закрывает). Позиционирование в `console.html:985-986` уходит под
  медиа-условие.
- `@media (hover:none)` — снять `:hover`-эффекты, которые на тач-экране залипают
  (`table.tbl tr:hover`, `console.html:99`; `circle.ideanode:hover`).

**Чего не делать.** Не переходить на canvas ради телефона, пока не измерено: 3 040 SVG-кругов
на мобильном движке могут держаться; мерить `performance.now()` вокруг `drawDial` на
реальном телефоне и решать по числу, а не по ощущению. Не прятать колонки «по-умному»:
скрытая колонка — это число, которого нет на экране, а мы уже договорились, что число либо
верное, либо отсутствует явно.

## §3 Проверки

Браузерной логики `selfcheck` не гоняет — Python-проверка HTML-страницы видит только текст.
Поэтому проверки делятся на три уровня, и первый из них новый.

**Самопроверка страницы.** В `console.html` добавить блок, который выполняется только при
`?selftest=1` и печатает в консоль браузера одну строку `SELFTEST OK` или падает на
первом `assert`:

- `parseHash("#ideas/idea_ab12") → {tab:"ideas", arg:"idea_ab12"}`, и обратно
  `formatHash` даёт исходную строку;
- `parseHash("#dial?q=a%20b&k=3")` возвращает параметры декодированными;
- `parseHash("")` → вкладка по умолчанию, без `arg`;
- `VIEW_STATE` после двух `switchTo` туда-обратно содержит прежний объект (тождество, не копия);
- «ближайшая метка» на синтетическом наборе марок выбирает попадание, а не лист, когда они
  в одной точке (проверка веса слоёв, `console.html:948`).

**`lake/api/selfcheck.py`** — статически, тем же способом, что уже проверяет `node --check`
и отсутствие идентификаторов озера:

- страница содержит блок `selftest` (иначе проверка выше молча исчезнет);
- в файле нет `let openIdea = () => {}` — заглушка, из-за которой всё это началось;
- есть `<meta name="viewport">`;
- есть медиа-запросы под 620 и 430 (иначе «адаптив» уедет с первым же рефакторингом);
- нет `top:53px` и других зашитых высот шапки.

**Ручной чек-лист** (телефон, 390×844, реальный аппарат, не эмулятор):

1. Открыть `/ui#dial`, ввести гипотезу пальцем, разложить — статус, круг, таблица помещаются.
2. Тап по узлу — карточка снизу; повторный тап — открылась идея; кнопка «назад» вернула круг с прежним запросом.
3. Переключить вкладку и вернуться — гипотеза и ответ на месте, повторного запроса нет (видно по логу сервера).
4. Ссылку с `#dial?q=…&run=1` открыть в новой вкладке — разложилось само, те же числа.
5. Таблицы «Идеи» и «Тезисы» читаются без горизонтального скролла.

## §4 Порядок

1. Роутер и `openIdea` (§2.1) — самое дешёвое и снимает дефект, который видно первым.
2. `VIEW_STATE` и параметры в URL (§2.2) — от него зависит пункт 3 ручного чек-листа.
3. Тач (§2.3, «Тач вместо ховера») — без него телефон бесполезен, это регрессия.
4. Раскладка и таблицы (§2.3, остальное).
5. Проверки (§3) — вместе с каждым пунктом, не в конце.

## §5 Открытые вопросы владельцу

1. **Что показывать на телефоне по умолчанию** — циферблат или retrieve? Сейчас первая
   вкладка `retrieve` (`console.html:1900`), а тыкать с телефона будут гипотезу.
2. **Нужна ли ссылка «поделиться»** отдельной кнопкой, или хватит того, что адрес и так
   стал воспроизводимым.
3. **`run=1` в ссылке** — согласовать: это единственный способ, которым консоль ходит в
   сеть без нажатия. Для `/dial` он безвреден (чтение индекса, лог не пишется), для
   `/retrieve` — нет, там строка в `retrieve.jsonl`. Предлагаю разрешить `run=1` только
   на циферблате.
