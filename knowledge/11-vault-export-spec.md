# 11 — Экспорт озера в Obsidian-vault (лёгкая спека)

Визуализация графа идей без единой строки кода отрисовки: озеро выгружается набором
markdown-файлов со ссылками `[[wikilink]]`, папка открывается в Obsidian, граф рисует он.

**Область:** только чтение из хранилища и запись файлов. Ни граф, ни индекс не меняются.
**Не входит:** свой рендер, D3/vis.js, веб-страница, правка заметок обратно в озеро.

---

## 1. Зачем именно так

`06:85` описывает двухслойную модель `IDEA ||--|{ THESIS`, а провенанс — критерий 4 ТЗ.
Обе вещи — это ровно граф со ссылками, то есть родная форма Obsidian. Любая своя
отрисовка означала бы новую зависимость и свой слой багов ради того, что уже есть.

Что даёт бесплатно: граф-вью с кластерами, поиск по всему тексту, фильтры и раскраска
по полю frontmatter, обратные ссылки (у тезиса видно его идею), локальный граф вокруг
узла. Ноль JS.

---

## 2. Форма выгрузки

```
data/vault/                     # gitignored, пересоздаётся целиком
  ideas/    idea-<id>.md
  theses/   thesis-<id>.md
  sources/  source-<id>.md
  README.md                     # что это, когда собрано, числа
```

Три типа заметок = три метки узлов. Имя файла — от id, а не от текста: текст идеи
меняется при пере-выводе (§4.6), а id держится специально, чтобы рёбра не рвались
(`08:200`). Читаемый заголовок живёт в `title` внутри файла.

### Идея — `ideas/idea-<id>.md`

```markdown
---
type: idea
id: idea_bd814a331168
leaves: 14
sources: 2
trust_score: 1.0986
rederived_at_leaf_count: 12
---
# LLM-directed evolution: an agent iteratively modifies entire code files

**Условия применимости.** …
**Ограничения.** …
**Режимы отказа.**
- …

| | |
|---|---|
| Заявленный эффект | … |
| Наблюдаемый эффект | … |

## Листья (14)
- [[thesis-th_14acea548f2d]] — +3.1 pp — Table 4
```

`effect_claimed` и `effect_observed` — две отдельные строки таблицы, никогда не склеены
(`06:200`).

### Тезис — `theses/thesis-<id>.md`

```markdown
---
type: thesis
id: th_14acea548f2d
idea: idea_bd814a331168
effect: "+3.1 pp"
locator: "Section 3.3"
---
> дословная формулировка тезиса

**Контекст.** cifar-10, resnet-18
**Идея:** [[idea-idea_bd814a331168]]
**Источник:** [[source-361e83702c426570]] · [ссылка](http://arxiv.org/abs/2509.19349v1)
```

### Источник — `sources/source-<id>.md`

Frontmatter: `type: source`, `id`, `kind` (paper/doc/run), `version`, `retrieved_at`,
для прогонов `run_success` и `run_meta`. Тело: заголовок, ссылка, список тезисов
`[[thesis-…]]`.

---

## 3. Что обязано быть правильным

1. **Ссылки двусторонние.** Идея перечисляет листья, лист называет идею и источник.
   Односторонний экспорт даёт в графе звёзды без обратных рёбер и убивает половину смысла.
2. **`[[` и `]]` внутри текста экранируются.** Тезисы — цитаты из статей, скобки там
   встречаются. Неэкранированные превращаются в битые ссылки, и в графе появляются
   узлы-призраки, которых нет в озере.
3. **Имя файла санируется**, но остаётся обратимым к id: `/ \ : * ? " < > |` в id не
   встречаются (`th_`/`idea_` + hex), так что достаточно проверить это ассертом, а не
   выдумывать схему кодирования.
4. **Экспорт пересоздаёт папку целиком.** Инкрементальное обновление оставило бы
   заметки удалённых узлов — граф показывал бы то, чего в озере нет.
5. **Число файлов сходится с `/stats`.** `ideas + theses + sources` из хранилища ==
   число `.md` минус `README.md`. Расхождение — это ошибка экспорта, и оно должно
   падать, а не молча дать неполный граф.
6. **Ничего не пишет в озеро.** Проверяется тем же приёмом, что в `lake/api/selfcheck.py`:
   отпечаток `data/` (размер, mtime) до и после, сравнение в `finally`.

---

## 4. Точки входа

Паритет обязателен: одно и то же и модулем, и по HTTP.

```python
lake.vault.export(dest: Path = DATA / "vault") -> dict   # {ideas, theses, sources, files, dest}
```

```bash
python3 -m lake.vault [--dest PATH]
```

HTTP — по желанию и последним: `POST /vault/export` возвращает тот же dict. Ручка
обязана ходить через ту же функцию, а не повторять её логику.

---

## 5. Размер и стоимость

Сейчас: 26 идей + 60 тезисов + 2 источника = **88 файлов**, единицы мегабайт.
На всём корпусе (84 источника, ~2500 тезисов, ≥120 идей) — около 2700 файлов; Obsidian
такое держит спокойно, но экспорт лучше не делать частью запроса.

Зависимостей ноль: чтение через `graph_client`, запись через `pathlib`. Векторы не
выгружаются — 384 float в markdown бессмысленны.

## 6. Проверка

`lake/vault.py` оставляет один `__main__` self-check, как остальные модули:
экспорт во временную папку на фикстуре из 2 идей / 3 листьев / 1 источника, и assert'ы —
счёт файлов сходится, каждая ссылка `[[…]]` указывает на существующий файл, `[[` в тексте
тезиса экранирована, реальный `data/` не тронут.

Живая приёмка: открыть `data/vault/` в Obsidian, посмотреть граф-вью. Ожидаемая картина —
26 сгустков (идея с листьями), два узла-источника, к которым сходится всё.

## 7. Чего сознательно нет

- **Рёбер идея↔идея.** Это блок B, `edge` пуста. Когда появятся — станут ещё одной
  секцией `## Связанные идеи` со ссылками и весом в тексте строки.
- **Обратного импорта.** Правка заметки не меняет озеро. Тезис неизменяем (§1.2), и
  редактируемый экспорт сделал бы вторую точку правды.
- **Автообновления.** Экспорт запускается руками после ингеста, а не по таймеру.
